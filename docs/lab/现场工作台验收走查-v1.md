# 现场工作台验收走查 v1

本清单用于活动前的功能验收。每个场景都启动独立的临时 SQLite 数据库，不会读取、写入或清空线上与日常本地数据。

## 启动方式

在 `tools/meetup-team-manager-site` 目录运行：

```bash
npm run acceptance:serve -- --scenario journey
```

终端会打印参与者、Staff 和 Admin 地址，以及只用于本地验收的 PIN。按 `Ctrl+C` 停止。每次重新运行都会生成一套全新的数据。

可用场景：

| 场景 | 命令 | 用途 |
| --- | --- | --- |
| `journey` | `npm run acceptance:serve -- --scenario journey` | 参与者、人员调度、队伍调度、发码、Workshop、资格确认 |
| `allocation` | `npm run acceptance:serve -- --scenario allocation` | 人工队优先、自由池自动分配预览与发布 |
| `tournament-group` | `npm run acceptance:serve -- --scenario tournament-group` | 冻结后的两组小组赛与赛果录入 |
| `tournament-knockout` | `npm run acceptance:serve -- --scenario tournament-knockout` | 已完成小组赛、淘汰赛生成、赛果锁定与晋级 |
| `admin` | `npm run acceptance:serve -- --scenario admin` | Code 回收、资格撤销、反馈与审计 |

## 参与者旅程

### P1：首次扫码登记

场景：`journey`。打开参与者入口，使用一个未出现过的昵称完成登记。

验收：

1. 页面立即显示一个 `P-xxx` 现场编号和“我的二维码”。
2. 状态为“等待工作人员安排队伍”，不会自动创建单人队。
3. 刷新页面后仍保持当前参与者身份。
4. 点击右上角“反馈”可以提交一条参与者反馈。

### P2：换手机恢复身份

场景：`journey`。在另一个浏览器或无痕窗口打开参与者入口，展开“换手机了？恢复我的状态”，输入刚才的昵称。

验收：

1. 恢复为相同的 `P-xxx` 和队伍状态。
2. 对于已领 Code 的参与者，换设备后不会直接泄露 Team Code；需要现场 Staff 再核验成员身份。

### P3：队伍、资源和比赛入口

场景：`journey`。直接打开终端打印的三个参与者链接：`已领资源`、`Workshop 中`、`已可参赛`。

验收：

1. `已领资源`：可见 Team Code、进入 Workshop、复制 Workshop 链接、打开/复制 Game Portal。
2. `Workshop 中`：可见资源入口和“完成练习赛后请 TA 确认”的下一步。
3. `已可参赛`：可见“已确认参加下午比赛”。
4. 三个页面均能打开“我的二维码”，二维码内容应对应各自 `P-xxx`。

## Staff 旅程

### S1：登录与页面稳定性

在任一场景打开 Staff 入口，用终端打印的本地验收 PIN 登录，昵称可填“验收 TA”。

验收：

1. 底部只显示 `现场 / 组队 / Workshop / 比赛` 四个高频入口。
2. 切换到任一 Tab 后，等待至少 5 秒自动刷新；当前 Tab、搜索条件和未提交输入不应跳回首页或被重置。

### S2：人员看板调度

场景：`journey`，进入“组队”。

预置数据：`验收-无队-01` 至 `验收-无队-05`、`验收-熟人甲/乙`、`验收-满队-甲/乙/丙`。

验收：

1. 第一屏先看到“人员 / 队伍”切换和人员搜索；自动分配不应挡住找人操作。
2. 搜索 `01`、`P-001` 或昵称，均可缩小人员列表。
3. 勾选 1–3 人后可以：组成新队、加入队伍、移出队伍。
4. 选择三名成员已满的 `验收-满队` 作为目标时，明确显示容量不足，不能提交。
5. 创建或移动提交后，只需要一次确认；重新加载后人员与队伍关系同步更新。

### S3：队伍看板反向调度

场景：`journey`，切换到“队伍”。

验收：

1. 可以完整浏览所有队伍，也可以按 `T-001`、`001` 或成员昵称查找。
2. 点击一支队伍打开配置：查看当前成员，添加人员，移出人员，转队，或移出全部成员而解散队伍。
3. 添加人员时可浏览完整候选列表；搜索和筛选只是加速，不是唯一入口。
4. 从队伍弹窗中可确认队伍、发放下一个 Code；Code 发放不用人工选择具体 Code。

### S4：自动分配

场景：`allocation`，进入“组队”后展开“自动分配与候补”。

预置数据：4 支人工队（2 人、2 人、3 人、1 人）和 36 名 `验收-自由池-xx` 人员。

验收：

1. 不展开时，人员和队伍看板仍在第一屏；展开后可看见自由、人工、自动、候补数量。
2. 点击“生成自动分配预览”时，不创建正式自动队，也不改变人员当前关系。
3. 预览明确列出人工队、自动队、候补和 seed。
4. 点击“发布预览”后，人工队核心成员保持原队；自由人员进入自动队，团队总数不超过 32，每队为 1–3 人。
5. 发布后刷新，分配结果应保持不变。

### S5：Workshop 与 TA

场景：`journey`，进入“Workshop”。

预置数据：`T-001` 已发资源，`T-002` 有“练习赛已完成，等待 TA 核验”备注，`T-003` 已确认可参赛。

验收：

1. 只展示已发 Code 的队伍；备注只在 Staff / Admin 页面可见。
2. 对 `T-002` 录入或修改备注后，可点击“确认可参赛”。
3. 确认后，队伍进入下午比赛资格池；参与者链接同步显示已确认状态。

## Admin 旅程

Admin 不是独立公开入口：先从 Staff 工作台右上角“更多”输入 Admin PIN 进入。以下操作只应在 Admin 可见。

### A1：异常资源与反馈

场景：`admin`。

预置数据：一支已解散且保留 Code 的队伍、一支已获资格队、两条反馈和对应审计。

验收：

1. 在资源页可找到已解散队伍，并选择回收 Code；回收后 Code 回到可用库存，能被另一支队伍自动领取。
2. 在资格页撤销 `验收-待撤销资格`；队伍退出比赛资格池，且撤销原因可追溯。
3. 反馈与审计页能看到两条验收反馈及关键动作；普通 Staff 和参与者看不到其他人的反馈内容。

### A2：比赛名单与赛程

场景：`tournament-group`。

预置数据：8 支已发 Code、已确认可参赛的 `T-001` 至 `T-008`。

验收：

1. Admin 可看到名单已冻结和两组小组赛；Staff 可录入小组赛赛果。
2. 每场录入后，积分榜更新胜/平/负、积分和净胜球；队名始终显示为 `T-xxx`，不会替换为 `A1/A2`。
3. 在任一小组赛尚未开始前，Admin 可以交换不同小组的两支队伍；录入赛果后该调整应被拒绝。
4. 所有小组赛完成后，Admin 可以生成淘汰赛。

### A3：淘汰赛与锁定

场景：`tournament-knockout`。

预置数据：两组小组赛已完成，淘汰赛已生成，尚未录入淘汰赛赛果。

验收：

1. 小组积分榜保留展示，但小组赛表单不可编辑，并明确说明已锁定。
2. Staff 可以为当前淘汰赛对阵录入非平局比分；胜者应自动进入下一轮。
3. 淘汰赛录入平局时系统必须拒绝，并提示需要重赛后录入。
4. Admin 可以作废赛程，返回到可重新分组的状态；这是例外操作，需确认后执行。
5. 打开 `/display`，现场大屏应显示当前小组积分、赛果和淘汰赛信息，且不泄露 Team Code 或备注。

## 尚需用真实环境手工确认的边界

- 实体手机对 Staff 二维码的相机扫码权限与低端设备滚动表现。
- 真实 AWS Workshop 链接、真实 Team Code 和 Game Portal 登录后的外部链路；本地场景仅验证本系统的跳转和复制行为。
- 多人同时操作同一条记录时的现场协作节奏；系统会拒绝版本冲突并要求刷新重试。
